# Event Bubbling in JavaScript

## Key Idea

Event bubbling is a DOM event propagation mechanism where an event starts at the target element and propagates upward through its ancestors toward the document root.

This allows parent elements to respond to events triggered by their children and forms the foundation of event delegation.

## 1. Event Propagation Phases

When an event occurs, it generally travels through these phases:

```
Capturing Phase:
Document → Parent → Target

Target Phase:
Target element

Bubbling Phase:
Target → Parent → Document
```

* Capturing: Event travels from the root toward the target.

* Target: Event reaches the element that initiated it.

* Bubbling: Event travels from the target back up through its ancestors.

> Not every event bubbles. For example, `click` bubbles, while `focus`, `blur`, and `mouseenter` do not normally bubble.

## 2. Basic Example

HTML

```
<div id="parent">
  <button id="child">Click me!</button>
</div>
```

JavaScript

```
const parent = document.querySelector("#parent");
const child = document.querySelector("#child");

parent.addEventListener("click", () => {
  console.log("Parent element clicked");
});

child.addEventListener("click", () => {
  console.log("Child element clicked");
});

child.click();
```

### Output

```
Child element clicked
Parent element clicked
```

The button's click event first executes its own handler and then bubbles to the parent.

## 3. Stopping Event Bubbling

Use `stopPropagation()` to prevent the event from continuing to other elements in the propagation path.

JavaScript

```
parent.addEventListener("click", () => {
  console.log("Parent clicked");
});

child.addEventListener("click", (event) => {
  console.log("Child clicked");

  event.stopPropagation();
});
```

### Output

```
Child clicked
```

The event does not bubble to the parent.

### `stopPropagation()` vs `stopImmediatePropagation()`

* `stopPropagation()` prevents the event from moving to other elements.

* `stopImmediatePropagation()` also prevents other listeners on the same element from executing.

> `stopPropagation()` does not stop other listeners attached to the same element.

## 4. Event Delegation

Event delegation means attaching one event listener to a common ancestor instead of adding separate listeners to every child.

It works primarily because of event bubbling.

### Without Delegation

JavaScript

```
button1.addEventListener("click", handleClick);
button2.addEventListener("click", handleClick);
button3.addEventListener("click", handleClick);
```

### With Delegation

JavaScript

```
const list = document.querySelector("#product-list");

list.addEventListener("click", (event) => {
  if (event.target.matches("button")) {
    console.log("Button clicked:", event.target.id);
  }
});
```

The parent receives clicks from its buttons through bubbling.

### Better Pattern: `closest()`

Checking `event.target.tagName` can fail when the button contains nested elements such as icons or spans.

JavaScript

```
list.addEventListener("click", (event) => {
  const button = event.target.closest("button");

  if (!button || !list.contains(button)) return;

  console.log("Clicked:", button.id);
});
```

`closest()` finds the nearest matching ancestor, including the target itself.

## 5. Benefits of Event Delegation

* Less code: One listener instead of many.

* Dynamic elements: Newly added children work automatically.

* Centralized logic: Event handling stays in one place.

* Reduced listener management: No need to add and remove listeners for every child.

> Delegation is not always faster. Modern browsers can handle many listeners efficiently. Its main advantages are dynamic content support, simpler management, and potentially reduced memory usage.

## 6. Practical Use Cases

### Product List

JavaScript

```
productList.addEventListener("click", (event) => {
  const button = event.target.closest("[data-action='buy']");

  if (!button) return;

  const productId = button.dataset.id;

  console.log("Buy product:", productId);
});
```

Example HTML:

HTML

```
<ul id="product-list">
  <li>
    <button data-action="buy" data-id="1">Buy Now</button>
  </li>
  <li>
    <button data-action="buy" data-id="2">Buy Now</button>
  </li>
</ul>
```

### Accordion

JavaScript

```
const accordion = document.querySelector(".accordion");

accordion.addEventListener("click", (event) => {
  const header = event.target.closest(".header");

  if (!header || !accordion.contains(header)) return;

  const content = header.nextElementSibling;
  content.classList.toggle("active");
});
```

### Dropdown

Event bubbling can help handle clicks inside a dropdown, but closing when the user clicks outside generally requires a listener on `document` and a containment check:

JavaScript

```
document.addEventListener("click", (event) => {
  const dropdown = document.querySelector("#dropdown");

  if (!dropdown.contains(event.target)) {
    console.log("Close dropdown");
  }
});
```

## 7. Common Pitfalls

### 1. Accidental Parent Handling

A parent listener may respond to events from children unintentionally.

Use:

JavaScript

```
event.target
```

or:

JavaScript

```
event.target.closest(".selector")
```

to identify the intended element.

### 2. Delegating Too High

Attaching a listener to `document` may capture unrelated events.

Prefer the nearest stable common ancestor when possible.

### 3. Nested Elements

This check can be unreliable:

JavaScript

```
if (event.target.tagName === "BUTTON") {
  // ...
}
```

A click on a `<span>` inside the button makes `event.target` the span.

Prefer:

JavaScript

```
const button = event.target.closest("button");
```

### 4. `stopPropagation()`

A child calling `stopPropagation()` can prevent an ancestor's delegated listener from receiving the event.

### 5. Event Order

For bubbling events, handlers execute from the target upward:

```
Button → Parent → Grandparent → Body → Document
```

The exact result also depends on the listeners and propagation behavior involved.

## 9. Interview Notes

* Event bubbling is enabled by default for events that support bubbling.

* `event.target` is the original event source.

* `event.currentTarget` is the element whose listener is executing.

* `stopPropagation()` stops movement between elements, not necessarily other listeners on the same element.

* Event delegation relies on bubbling and is useful for dynamic lists.

* Use `closest()` rather than checking only `tagName`.

* `focus` and `blur` do not bubble; `focusin` and `focusout` do.

* React uses a centralized event system for many events, but delegation decisions still depend on the specific use case.

## TL;DR

> Event bubbling moves an event from its target element up through its ancestors. It allows parent elements to respond to child events and enables event delegation, where one ancestor listener handles events from multiple children. Use `event.target`, `closest()`, and `stopPropagation()` when controlling event behavior.
