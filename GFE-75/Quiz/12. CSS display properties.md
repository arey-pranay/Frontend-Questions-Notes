# CSS `display` Property

## Key Idea

`display` determines **how an element participates in layout**—whether it generates a box, how that box behaves, and how its children are laid out.

```css
.element {
  display: flex;
}
```

It controls both the element's **outer layout behavior** and, for values like `flex`/`grid`, the **layout model of its children**.

---

## Common Values

| Value          | Behavior                                             | Typical Use                            |
| -------------- | ---------------------------------------------------- | -------------------------------------- |
| `none`         | Removed from layout entirely                         | Hide elements                          |
| `block`        | Starts on a new line; normally fills available width | Sections, containers                   |
| `inline`       | Flows alongside surrounding text                     | `<span>`, `<a>`                        |
| `inline-block` | Flows inline but accepts `width`/`height`            | Sized inline elements                  |
| `flex`         | Block-level flex container                           | 1D layouts                             |
| `inline-flex`  | Inline-level flex container                          | Flex component inside text/inline flow |
| `grid`         | Block-level grid container                           | 2D layouts                             |
| `inline-grid`  | Inline-level grid container                          | Grid that participates in inline flow  |
| `table`        | Behaves like `<table>`                               | Table-like layouts                     |
| `list-item`    | Behaves like `<li>`                                  | List items                             |

`table-row` and `table-cell` similarly reproduce table layout behavior.

---

## `display: none`

```css
.modal {
  display: none;
}
```

The element:

* Takes **no space**.
* Is removed from normal layout.
* Its descendants aren't rendered as part of the page.
* The layout behaves as though the element isn't there.

To show it:

```css
.modal {
  display: block;
}
```

⚠️ This is different from merely making something invisible.

---

# Hiding Elements: `display` vs `visibility` vs `opacity`

| Property             | Visible? | Takes space? | Normally interactive? |
| -------------------- | -------- | ------------ | --------------------- |
| `display: none`      | ❌        | ❌            | ❌                     |
| `visibility: hidden` | ❌        | ✅            | ❌                     |
| `opacity: 0`         | ❌        | ✅            | ✅ potentially         |

### `visibility`

```css
.element {
  visibility: hidden;
}
```

The element remains in the layout, so its space is preserved.

### `opacity`

```css
.element {
  opacity: 0;
}
```

The element is transparent but still participates in layout. It can also remain hit-testable/interactable depending on the situation.

**Interview trap:** `opacity: 0` is **not equivalent to `display: none`**.

---

# `display: block`

```css
div {
  display: block;
}
```

A block-level box:

* Starts on a new line.
* Normally takes the available width.
* Allows explicit `width` and `height`.
* Vertical margins/padding affect layout.

Common examples:

```html
<div>
<section>
<p>
<header>
<footer>
```

---

# `display: inline`

```css
span {
  display: inline;
}
```

An inline box:

* Flows with surrounding text/content.
* Doesn't start a new line.
* `width` and `height` don't apply in the normal way.
* Horizontal margins/padding affect layout.
* Vertical padding/border can visually extend outside the line box without behaving like a block's height.

Examples:

```html
<span>
<a>
<strong>
<em>
```

---

# `display: inline-block`

```css
button {
  display: inline-block;
  width: 200px;
  height: 50px;
}
```

Combines important characteristics:

```text
inline behavior
      +
block-like sizing
```

So it:

* Can sit beside other inline/inline-block elements.
* Accepts `width` and `height`.
* Allows margins and padding on all sides to affect layout.

Useful for small inline components, though **Flexbox/Grid are generally preferred for larger layouts**.

---

# `display: flex`

```css
.container {
  display: flex;
}
```

Creates a **flex container**.

Its direct children become **flex items**.

```css
.container {
  display: flex;
  justify-content: space-between;
  align-items: center;
}
```

Useful for **one-dimensional layouts**:

* Row navigation
* Centering
* Toolbars
* Cards in a row/column
* Aligning items

Important distinction:

```text
display: flex
→ outer behavior is block-level
→ children use Flexbox
```

`inline-flex` makes the flex container itself participate in inline flow.

---

# `display: grid`

```css
.container {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 16px;
}
```

Creates a **grid container**.

Its direct children become grid items.

Best suited for **two-dimensional layouts**:

```text
columns + rows
```

For example:

```text
┌─────┬─────┬─────┐
│  1  │  2  │  3  │
├─────┼─────┼─────┤
│  4  │  5  │  6  │
└─────┴─────┴─────┘
```

---

# `display: table`

CSS can reproduce table layout behavior:

```css
.table {
  display: table;
}

.row {
  display: table-row;
}

.cell {
  display: table-cell;
}
```

Equivalent conceptually to:

```html
<table>
  <tr>
    <td>...</td>
  </tr>
</table>
```

Today, use actual semantic `<table>` elements for tabular data rather than recreating tables with CSS.

---

# `display: list-item`

```css
.item {
  display: list-item;
}
```

Makes the element behave like a list item and allows list-marker behavior such as:

```css
.item {
  list-style-type: disc;
}
```

Normally used through:

```html
<li>
```

rather than manually setting `display: list-item`.

---

# Important Concept: Outer vs Inner Display

Modern CSS conceptually separates:

```text
Outer display → how the element participates in its parent's layout
Inner display → how its children are laid out
```

For example:

```css
.container {
  display: flex;
}
```

means roughly:

```text
block-level outside
+
flex layout inside
```

Similarly:

```css
.container {
  display: inline-flex;
}
```

means:

```text
inline-level outside
+
flex layout inside
```

This explains why:

```text
flex vs inline-flex
grid vs inline-grid
```

are different.

# Interview Traps ⭐

### `display: none` vs `visibility: hidden`

```text
display: none
→ no layout space

visibility: hidden
→ space remains
```

### `display: flex` doesn't make the element inline

```css
display: flex;
```

is **block-level outside**.

For inline behavior:

```css
display: inline-flex;
```

### `display: inline-block`

Think:

> **Inline positioning + block-like dimensions**

### Flex vs Grid

```text
Flex → primarily 1D → row OR column
Grid → primarily 2D → rows AND columns
```

This isn't an absolute rule—Flexbox can wrap and Grid can be used for simple one-dimensional layouts—but it's the useful interview mental model.

### `display` is not the same as `visibility`

`display` can completely remove an element from layout; `visibility` preserves its layout space.

# Practical Cheat Sheet

```css
/* Hide */
display: none;

/* Normal layout */
display: block;

/* Text-like */
display: inline;

/* Inline + explicit dimensions */
display: inline-block;

/* One-dimensional layout */
display: flex;

/* Inline flex container */
display: inline-flex;

/* Two-dimensional layout */
display: grid;

/* Inline grid container */
display: inline-grid;
```

## TL;DR

> **`display` controls how an element participates in layout and, for container values such as `flex` and `grid`, how its children are laid out.**

```text
none         → removed from layout
block        → new line, block-level
inline       → flows with text
inline-block → inline + width/height
flex         → block-level Flexbox container
inline-flex  → inline-level Flexbox container
grid         → block-level Grid container
inline-grid  → inline-level Grid container
```

**Most useful interview comparison:**
`block` = new line, `inline` = same line, `inline-block` = same line + controllable dimensions, `flex/grid` = layout systems.
