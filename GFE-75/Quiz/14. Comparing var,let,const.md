# `var` vs `let` vs `const`

## Key Idea

The main differences are **scope, reassignment, redeclaration, and hoisting**.

|                              | `var`       | `let`              | `const`            |
| ---------------------------- | ----------- | ------------------ | ------------------ |
| Scope                        | Function    | Block              | Block              |
| Can reassign?                | ✅           | ✅                  | ❌                  |
| Can redeclare in same scope? | ✅           | ❌                  | ❌                  |
| Hoisted?                     | ✅           | ✅                  | ✅                  |
| Access before declaration    | `undefined` | ❌ `ReferenceError` | ❌ `ReferenceError` |
| Must initialize?             | ❌           | ❌                  | ✅                  |

---

## 1. `var` — Function Scoped

```js
function test() {
  if (true) {
    var x = 10;
  }

  console.log(x); // 10
}
```

`var` ignores block boundaries such as `if`, `for`, and `while`.

It is scoped to the **nearest function**.

```js
function test() {
  var x = 10;
}

console.log(x); // ReferenceError
```

### Reassignment ✅

```js
var x = 10;
x = 20;
```

### Redeclaration ✅

```js
var x = 10;
var x = 20; // allowed
```

This ability to accidentally redeclare variables is one reason modern JavaScript generally prefers `let`/`const`.

---

## 2. `let` — Block Scoped

A block is generally anything surrounded by `{}`:

```js
if (true) {
  let x = 10;
}

console.log(x); // ReferenceError
```

Unlike `var`, `let` respects block boundaries.

### Reassignment ✅

```js
let x = 10;
x = 20;
```

### Redeclaration ❌

```js
let x = 10;
let x = 20;
// SyntaxError
```

But a different nested scope can have the same variable name:

```js
let x = 10;

{
  let x = 20;
  console.log(x); // 20
}

console.log(x); // 10
```

These are two different bindings.

---

## 3. `const` — Block Scoped + No Reassignment

```js
const x = 10;

x = 20;
// TypeError
```

Like `let`, `const` is block-scoped and cannot be redeclared in the same scope.

```js
const x = 10;
const x = 20;
// SyntaxError
```

### Important: `const` does NOT make objects immutable

This is a common interview trap:

```js
const user = {
  name: "Pranay"
};

user.name = "Alex"; // ✅ allowed
```

The **binding** cannot be reassigned:

```js
user = {}; // ❌ TypeError
```

But the object itself can still be mutated.

For true immutability, you need mechanisms such as `Object.freeze()` or immutable programming patterns.

# Hoisting

All three declarations are **hoisted**, but they behave differently.

### `var`

```js
console.log(x); // undefined

var x = 10;
```

Conceptually:

```js
var x;
console.log(x);
x = 10;
```

The declaration is hoisted and initialized with `undefined`.

---

### `let` and `const`

```js
console.log(x); // ReferenceError

let x = 10;
```

They are also hoisted, but **not initialized before their declaration is evaluated**.

The period between entering the scope and reaching the declaration is called the **Temporal Dead Zone (TDZ)**.

```js
{
  // TDZ for x
  console.log(x); // ReferenceError

  let x = 10;
  // x is initialized here
}
```

Same applies to `const`.

> **Interview trap:** Saying "`let` and `const` are not hoisted" is technically incorrect. They are hoisted, but remain uninitialized in the TDZ.

---

# The Classic `var` vs `let` Loop Difference

This is particularly important in interviews.

### `var`

```js
for (var i = 0; i < 3; i++) {
  // ...
}

console.log(i); // 3
```

`i` is function-scoped.

### `let`

```js
for (let i = 0; i < 3; i++) {
  // ...
}

console.log(i); // ReferenceError
```

`i` is scoped to the `for` block.

This also matters with closures:

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}

// 3
// 3
// 3
```

With `let`:

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}

// 0
// 1
// 2
```

Each iteration gets its own `let` binding.

---

# `let` vs `const`: Practical Rule

Prefer:

```js
const user = getUser();
```

when the variable won't be reassigned.

Use:

```js
let count = 0;

count++;
```

when reassignment is required.

Avoid `var` in modern code unless you're working with legacy code or specifically need its behavior.

## Interview Mental Model

```text
var
 ├─ Function scoped
 ├─ Reassign ✅
 ├─ Redeclare ✅
 └─ Hoisted + initialized as undefined

let
 ├─ Block scoped
 ├─ Reassign ✅
 ├─ Redeclare ❌
 └─ Hoisted + TDZ

const
 ├─ Block scoped
 ├─ Reassign ❌
 ├─ Redeclare ❌
 ├─ Must initialize
 └─ Hoisted + TDZ
```

### One-liner

> **`var` is function-scoped and freely redeclarable; `let` is block-scoped and reassignable; `const` is block-scoped and not reassignable. `let`/`const` are hoisted but live in the TDZ until initialized.**
