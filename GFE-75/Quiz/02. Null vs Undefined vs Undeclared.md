# `null` vs `undefined` vs Undeclared

## Key Idea

These represent **three different states**:

| State       | Meaning                             | `typeof`       | Accessing directly |
| ----------- | ----------------------------------- | -------------- | ------------------ |
| `null`      | Explicitly says **"no value"**      | `"object"` ⚠️  | `null`             |
| `undefined` | Declared, but **no value assigned** | `"undefined"`  | `undefined`        |
| Undeclared  | Identifier **doesn't exist**        | `"undefined"`* | `ReferenceError`   |

> `typeof` is the interesting exception: `typeof undeclaredVariable` safely returns `"undefined"` instead of throwing.

---

## `undefined`

The variable exists, but currently has no assigned value.

```js
let foo;

console.log(foo); // undefined
console.log(foo === undefined); // true
console.log(typeof foo); // "undefined"
```

Also commonly produced when:

* A function doesn't explicitly return anything.
* An object property doesn't exist.
* An array element is missing.

```js
function foo() {}

const result = foo(); // undefined
```

### Checking

Prefer:

```js
value === undefined
```

or:

```js
typeof value === "undefined"
```

The latter is particularly useful when the identifier itself **might not exist**.

---

## `null`

`null` is an **explicitly assigned absence of a value**.

```js
const user = null;

console.log(user === null); // true
```

Think:

> `undefined` → "I don't have a value yet."
> `null` → "I intentionally have no value."

### Checking

```js
value === null
```

⚠️ Famous JavaScript quirk:

```js
typeof null === "object"; // true
```

This is a historical JavaScript bug/legacy behavior. **Never use `typeof` to check for `null`.**

---

## Undeclared

The identifier has **never been declared** with `let`, `const`, `var`, etc.

```js
console.log(x);
// ReferenceError: x is not defined
```

Historically, non-strict JavaScript could accidentally create globals:

```js
function foo() {
  x = 1; // bad practice
}

foo();
console.log(x); // 1
```

In **strict mode**, this throws:

```js
"use strict";

x = 1; // ReferenceError
```

Always declare variables explicitly.

---

## How to Check Safely

This is an important interview distinction.

### Checking whether an identifier exists

```js
typeof x === "undefined"
```

is safe even if `x` is undeclared:

```js
typeof x; // "undefined"
```

Whereas:

```js
x === undefined
```

throws:

```text
ReferenceError: x is not defined
```

if `x` is undeclared.

### Checking a value that already exists

If you already have a variable/value:

```js
value === undefined
value === null
```

Use strict equality (`===`).

---

## `null == undefined`

JavaScript's loose equality considers them equal:

```js
null == undefined; // true
```

But:

```js
null === undefined; // false
```

Therefore, **don't use `==` when distinguishing them**.

```js
value == null
```

is sometimes intentionally used as a shorthand for:

```js
value === null || value === undefined
```

But in interviews and production code, explicitly writing the two checks is often clearer.

## Interview Traps ⭐

### 1. Why is `typeof null === "object"`?

Historical JavaScript behavior. It's a well-known language quirk.

### 2. Why does `typeof undeclaredVariable` not throw?

`typeof` has special behavior for an unresolvable identifier:

```js
typeof unknown; // "undefined"
```

This makes it useful for existence checks.

### 3. `undefined` can technically be reassigned?

Historically, `undefined` could be overwritten in some environments. Modern best practice is to use `=== undefined` or `typeof x === "undefined"` rather than relying on assigning/redefining it. `globalThis.undefined` is now a non-writable property in modern ECMAScript environments.

### 4. Undeclared ≠ `undefined`

This distinction is critical:

```js
let a;
console.log(a); // undefined

console.log(b); // ReferenceError
```

`a` **exists** and has the value `undefined`; `b` **doesn't exist**.

---

## Best Practice

* Always declare variables with `const`/`let` (or `var` only when legacy behavior is required).
* Use `null` when you intentionally want to represent "no value".
* Use `=== null` for `null`.
* Use `=== undefined` when checking an existing value.
* Use `typeof x === "undefined"` when `x` itself may be undeclared.
* Enable **ESLint/TypeScript** to catch undeclared or incorrectly referenced variables.

## TL;DR

```text
null       → explicitly "no value"
undefined  → declared, but no value
undeclared → identifier doesn't exist

typeof null        → "object"       ⚠️
typeof undefined   → "undefined"
typeof undeclared  → "undefined"    ⚠️ safe

null === undefined → false
null == undefined  → true
```

**Most important interview distinction:**
`undefined` is a **value**; undeclared means the **identifier itself doesn't exist**.
